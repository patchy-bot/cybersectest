### 1. web2/exec/app.py
**Vulnerability:** CODE_INJECTION  
**Confidence:** HIGH  
**Breaking Changes:** Yes

**Explanation:** Replaced arbitrary exec/eval with a restricted AST-based evaluator. The SafeEval visitor forbids any nodes outside basic arithmetic. eval is called with an empty __builtins__ to prevent access to dangerous functions.

**Security Notes:** Ensure any future extension to allowed operators is validated. Consider using a dedicated sandbox library for complex requirements.

**Additional Dependencies:**
- ast

**Testing Recommendations:**
- Test valid arithmetic expressions: '2+2', '3*5-1'
- Test disallowed inputs: '__import__', 'open("/etc/passwd")'
- Fuzz with random strings to ensure rejection

### 3. web3/param/gateway.php

**Breaking Changes:** Yes

**Explanation:** Added session-based authentication and CSRF token validation. Only JSON POST with a matching CSRF token is processed. Inputs are cast and length-limited.

**Security Notes:** Ensure HTTPS is enforced. Regenerate CSRF token periodically.

### 4. web4/exec/app.py

**Confidence:** HIGH

**Explanation:** Removed use of $where entirely. Validated that username is alphanumeric and used a direct field match in find_one, eliminating injection risk.

**Security Notes:** For more complex queries, use parameterized query operators and never interpolate user input into JavaScript code.
