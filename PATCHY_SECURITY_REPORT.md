## 🔧 Security Fixes Provided


### 1. web2/exec/app.py
**Vulnerability:** CODE_INJECTION  
**Confidence:** HIGH  
**Breaking Changes:** No

**Explanation:** Removed use of Python exec() on raw input. Instead we parse the input into an AST and enforce a whitelist of safe nodes to prevent arbitrary code execution. We then compile and eval only safe expressions in a restricted namespace where __builtins__ is empty.

**Security Notes:** - This restricts evaluation to basic arithmetic and literal data types.  
- If more operations are needed (e.g., math functions), explicitly add safe names into the eval namespace.  
- Logging / rate limiting can prevent abuse.

**Additional Dependencies:**

**Testing Recommendations:**
- Submit valid arithmetic exprs and verify results

### 4. web4/exec/app.py
**Vulnerability:** NOSQL_INJECTION  
**Confidence:** HIGH  
**Breaking Changes:** No

**Explanation:** Removed use of MongoDB’s $where operator with string interpolation. Instead, we perform a direct field match on the username, after validating it against an allowlist pattern. This prevents arbitrary JavaScript execution in the database query.

**Security Notes:** - Always validate and sanitize input before using it in database operations.  
- Use explicit projections to limit fields returned.  
- For more complex filters, use aggregation pipelines with parameter binding.

**Additional Dependencies:**
None

**Testing Recommendations:**
- Attempt NoSQL payloads (e.g., {$gt: ''}) and confirm failure
- Test valid usernames return correct records
